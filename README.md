## Шаг 2. Что видит программа

- `Cores: 12`
- `Logical processors: 16`
- `Base speed: 2.20 GHz`

Операционная система планирует потоки выполнения (`threads`) именно на логические процессоры. Программе не важно, сколько физических кремниевых ядер внутри - программа видит лишь "виртуальные" очереди задач, которые ей предоставляет ОС.

## Шаг 3. Один поток нагружает процессор

- Загрузка процессор поднималась до `15%` (при максимальных `6%` без выполнения кода).
- Частота повышалась до `2.40 GHz` (при максимальных `1.00 GHz` без выполнения кода)

## Шаг 5. Изменяем количество потоков

| Количество потоков | Примерная загрузка CPU |
| :----------------: | :--------------------: |
|         1          |           15           |
|         2          |           18           |
|         4          |           30           |
|         8          |           53           |
|         16         |          100           |

**Вывод**: чем больше количество работающих потоков, тем больше загружен CPU.
После достижения определенного количества потоков дальнейшее их увеличение перестает заметно повышать загрузку процессора из-за физических ограничений архитектуры процессора и накладных расходов операционной системы

## Шаг 6. Ядра и логические процессоры

- `Физические ядра: 12`
- `Логические процессоры: 16`

Количество физических ядер и логических процессоров может отличаться благодаря технологиям `Hyper-Threading` (или `SMT` - `Simultaneous Multithreading`): одно ядро может обрабатывать сразу два потока, для свои ресурсы (кэш, регистры). Из-за этого 12 физических ядер ОС превращают в 16 логических.

## Шаг 7. Частота процессора

- `Частота, когда программа ничего не считает: 1.00 GHz`
- `Частота, во время нагрузки: 2.75 GHz`

Современные процессоры используют технологии динамического изменения частоты. В простое частота снижается для экономии энергии и уменьшения нагрева, а при высокой нагрузке процессор автоматически разгоняется выше базовой скорости для увеличения производительности.

## Итоговый вопрос

Если у процессора 4 физических ядра и 8 логических ядер, а программа сообщает: `Environment.ProcessorCount == 8`, то это не противоречия. Программа видит число логических процессоров, которые можно использовать для выполнения потоков.

## Контрольные вопросы

1. `Environment.ProcessorCount` показывает число логических процессоров.
2. Физическое ядро - это реальный компонент процессора (кремниевый блок с собственными аппаратными компонентами), а логический процессор - это поток, виртуальное разделение этого ядра на независимые линии обработки.
3. Увеличение количества потоков увеличивает загрузку CPU, потому что программа начинает задействовать сразу несколько логических процессоров (т.е. большую часть CPU, чем обычно).
4. Это происходит из-за ограничений физической архитектуры процессора. Если потоков становится больше, чем логических процессоров, они больше не могут выполнятся одновременно. Процессору приходится постоянно переключаться между ними (это называется переключение контекста). Это создаёт накладные расходы, и общая полезная нагрузка перестаёт расти, а иногда и падает.
5. Процессор автоматически регулирует частоту в зависимости от текущих задач, температуры, энергопотребления, чтобы балансировать между производительностью и экономией энергии.
